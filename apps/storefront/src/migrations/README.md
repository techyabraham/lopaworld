# Payload migrations

Generated by `pnpm payload migrate:create <name>` from the repository root (runs the Payload CLI with `--use-swc`; it does not connect to the database). Review the SQL before committing and keep every change backward compatible (expand → migrate → contract).

`index.ts` is imported by `payload.config.ts` as `prodMigrations`, so the app applies pending migrations itself when Payload first connects with `NODE_ENV=production`. The container does not run `payload migrate`.

`20261105_144453_initial_schema` is the baseline. Its first statement, `CREATE SCHEMA IF NOT EXISTS "payload"`, was added by hand during review, because Payload only creates its schema when it creates the whole database.

These files are excluded from ESLint.
