# Lopaworld codebase audit — 5 November 2026

**Scope:** `techyabraham/lopaworld` at commit `2a2e274` ("handover setup"), ~3,000 lines of first-party TypeScript/CSS across `apps/storefront`, `apps/medusa` and four `packages/*`, plus all of `docs/`.
**Method:** full source read. Nothing was installed, built or run for this audit. Every claim below cites a file. Claims marked **(verify)** come from reading the code and framework defaults and must be reproduced before acting on them.

---

## 1. Verdict

The previous agent built a **careful, honest foundation**. It is not yet a store. The data boundaries are right (Medusa for commerce, Payload for editorial). The Paystack provider is more careful than most production code: it verifies amount, currency and reference on every step, uses HMAC-SHA512 with constant-time compare, and makes deterministic references. The documentation discipline (`OPEN_ITEMS.md`, `TODO_CONFIRM:` markers, no invented facts) is excellent. **Keep all of that.**

What it is not:

| Dimension | Current state | Gap to "better than the best Shopify stores" |
|---|---|---|
| Deployability | Cannot produce a production build or a Payload schema; deploy files untested | Must build green in CI and boot on a clean VPS |
| Performance | Every page is fully dynamic, nothing is cached, images are unoptimised | Should be edge-cached HTML, per-entity revalidation, AVIF images |
| Catalogue | Loads up to 100 products and filters them in memory | Server-side faceted search with typo tolerance |
| Design | Generic ivory/Bodoni luxury template | A distinct visual identity that is Lagos-loud |
| Differentiators | None (standard PLP/PDP/cart/checkout) | Made-to-measure, aso-ebi group orders, occasion shopping, WhatsApp-native service |
| Operations | One Medusa process, local disk media, no backups, builds on the production box | Server/worker split, object storage, off-site backups, images built in CI |

## 3. Architecture and operations (what I would change)

1. **Build images in GitHub Actions, not on the VPS.** Coolify building a Next.js + Medusa monorepo on the same 8 GB box that runs Postgres will cause out-of-memory errors or starve the live site during each deploy. CI should build and push to GHCR, then trigger a Coolify deploy webhook. Coolify then only pulls.
2. **Take Postgres and Redis out of the app compose.** Run them as Coolify *standalone database resources*. That provides Coolify's scheduled S3 backups (to Cloudflare R2 or Backblaze B2) and keeps database lifecycle separate from app deploys. A `docker compose down` on the app can then never touch data.
3. **Split Medusa into `medusa-server` and `medusa-worker`** using the same image with `MEDUSA_WORKER_MODE`, and disable the admin on the worker. Configure Redis-backed event bus, workflow engine, locking and caching modules. Today only the session store uses Redis, which Medusa does not support for production.
4. **Put media in Cloudflare R2** for Payload (`@payloadcms/storage-s3`) and Medusa (the S3 file provider). This removes two Docker volumes that would otherwise need their own backup story.
5. **Put Cloudflare in front of the VPS** (proxied DNS, Full-strict TLS) with cache rules for `/_next/static/*`, `/_next/image*` and cached HTML. It acts as a free CDN and DDoS shield in front of a single VPS in Germany, with edge POPs in Lagos.
6. **Run Payload migrations through `prodMigrations`** in the Postgres adapter, so they run inside the app process on init. This removes the CLI-in-container path that is broken.
7. **Cache with tags and revalidate on change.** Use Next 16 cached fetches with `cacheTag('product:<handle>')` etc. A Medusa subscriber on `product.updated` / `inventory-level.updated` and Payload `afterChange` hooks call a secret-protected `/api/revalidate`. HTML becomes cacheable and stays fresh to within seconds.
8. **Meilisearch** for search and faceted listings, synced from Medusa subscribers. It handles typo tolerance and synonyms (e.g. agbada = agbadda, senator = native, kaftan = caftan, buba, iro, gele, fila, jalamia). Medusa's `q` is a plain text match.
9. **Observability:** Sentry (errors and traces) for both apps, Uptime Kuma (a Coolify one-click service) for health endpoints, structured JSON logs, and Coolify notifications to email or Telegram.

## 4. Design critique of what was built

- **Generic.** Ivory canvas, Bodoni display, DM Sans, 0.5–0.9 rem radii and soft card shadows (`packages/ui/tokens/tokens.css`) are the default "luxury Shopify theme". Nothing about it says Lagos or says *Look Important*.
- **Seven competing accent colours** (`[data-label=…]` tokens) fragment the house. Labels should differ by photography and type voice, not by hue.
- **"Lopaworld" is modelled as a seventh label** (`packages/types/src/index.ts:8`). It is the parent house. This muddles navigation ("Lopaworld — The House" appears as a label tile) and catalogue metadata. **Owner decision required** (the master brief fixed seven slugs).
- **The homepage has no signature moment.** It is a hero, then a grid of label tiles, then "Instagram picks".
- **Copy uses placeholder text instead of product features**, e.g. "WhatsApp support details will be available here after confirmation" on every product page. The rule against inventing facts is right, but the answer is to hide the module until it is configured, not to show placeholder text to customers.
- **Rich product information is missing:** no stock urgency, no delivery estimate, no fit matching, no "complete the look", no on-model video.

The direction I proposed in the earlier design canvas ("LopaWorld Storefront") fixes these: one house palette, condensed heavy type, a hero that changes per label, occasion-first navigation, made-to-measure as a product mode, aso-ebi group orders, WhatsApp as a sales channel, and multi-currency display.

**Contrast correction to that canvas:** signal red `#D93A1E` on paper `#F7F6F3` is **4.25:1, which fails AA** for body-size text. Use `#B8301A` (5.59:1) for any red text, and keep `#D93A1E` only for fills behind white text (4.59:1) or for display-size type.

## 5. Benchmarks to beat (what to borrow, not copy)

| Store | Borrow |
|---|---|
| SSENSE | Editorial and commerce in one flow; very fast, text-led listings |
| Mr Porter | "Complete the look" and fit advice on the product page; The Journal |
| Aimé Leon Dore | Brand world first: drops, campaigns, a café-as-story tone |
| Jacquemus | A product page built around motion and a bold campaign |
| Kith | Drop mechanics: countdown, notify-me, sold-out as a status symbol |
| Net-a-Porter | Delivery promise shown before the bag ("Arrives tomorrow") |

None of them offer **made-to-measure with a stored fit profile** or **group orders paid per guest**. Those two features alone put Lopaworld ahead for its market.
